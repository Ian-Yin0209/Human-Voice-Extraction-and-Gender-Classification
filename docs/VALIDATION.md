# Validation

## 0.3.0 MIMO integration: 2026-10-22

The fixed Sony MIMO-SCNet small checkpoint passed real CPU inference on Windows/Python 3.12.14. Both the explicit network fetch command and local-ZIP install path completed with the pinned archive and extracted-weight SHA-256 values.

The [machine-readable record](validation/2026-10-22-mimo-cpu.json) contains two generated-audio cases: a two-second 16 kHz stereo tone resampled to 88,200 stereo frames through five overlapping chunks, and a one-frame 8 kHz mono clip resampled to six stereo frames. Four stem WAVs and an accompaniment WAV were read back to check length, rate, channels and finite samples. Maximum mixture reconstruction error was below `1e-7` for both cases. This is a compatibility check, not an audio-quality benchmark. No GPU or reference-music dataset evaluation was performed.

Reproduce without downloading models implicitly:

```sh
python -m pip install '.[modern]'
voice-extract fetch-model mimo-scnet --models-dir models
python examples/mimo_smoke.py --weights models/mimo-scnet-small-v1.pth --output-dir new-mimo-smoke
```

The fetch command is the explicit download step. The smoke script and separation command read only local files. The output directory must be new. `report.json` and `compatibility.json` describe the run and generated fixture.

New automated checks cover download integrity and rollback, new-output-directory protection, chunk overlap/tail handling, output validation, optional-runtime boundaries and the numerical definition of SI-SDR. Most use small fixtures or an injected separator; they do not download or benchmark pretrained weights. The separately recorded real-checkpoint run above is distinguished from these tests. Windows tests that cannot create symbolic links are skipped locally; Linux CI exercises those paths.

For research sources, model terms, chunking and metric limitations, see [Research](RESEARCH.md).

## Local checks: 2026-10-21

Environment: Windows 10, Python 3.12.14, CPU. The optional model runtime was installed in an isolated environment outside the source tree.

| Check | Result |
| --- | --- |
| Unit and CLI regressions | The original 47 tests passed with no skips when PyTorch was installed; the additional ASCII-console Unicode-path regression passed separately (48 tests in total). |
| Static checks | `python -m ruff check .` passed. |
| Distribution build | Source archive and pure-Python wheel built successfully. |
| Installed-wheel entry point | `voice-extract --version`, `inspect --json`, and `prepare` ran outside the checkout. |
| Two-stem pretrained checkpoint | Loaded both U-Nets and ran inference on generated stereo audio. Outputs were finite, 44.1 kHz, two channels, and exactly 88,200 frames. |
| Legacy classifier weights | Upstream HDF5 weights loaded; Mel extraction and inference returned finite binary-label scores. |

The initial separation smoke test used an original two-second stereo 440/660 Hz tone generated by `examples/generate_demo.py` at 16 kHz. It exercised the adapter's resampling to 44.1 kHz. The maximum absolute error between the sum of both stems and the resampled mixture was `1.4901161193847656e-08`.

Full runtime versions, fixed upstream source URLs, byte counts, checksums, and measured run times are in [the JSON record](validation/2026-10-21-windows.json). Run times are observations from one environment, not performance promises.

## Reproduce the compatibility smoke test

Obtain the external model files yourself from the upstream sources linked in [Provenance](PROVENANCE.md), then run:

```sh
python -m pip install '.[models]'
python examples/model_smoke.py --checkpoint models/2stems/model --weights models/model.h5 --output-dir smoke-results
```

The output directory must not exist. This generates an original two-second 44.1 kHz stereo tone, runs both adapters, checks finite output and mixture reconstruction, and writes `report.json` with package versions and SHA-256 checksums. No weights or media are downloaded by the script.

## Scope

These are software compatibility and regression checks. A tone is not speech or music, and successful inference does not establish separation quality, classifier accuracy, calibration, demographic coverage, or real-world usefulness. There is no independent quality benchmark or external adoption claim.

CI is configured for Python 3.10, 3.11 and 3.12 on Linux and Windows, with a separate CPU PyTorch job. The local record above verifies only the stated Windows/Python environment; remote CI outcomes must be checked separately.

The first remote CI run passed Linux and CPU PyTorch checks but exposed a Windows ANSI-console failure: writing an unrepresentable filename to stdout turned otherwise successful audio processing into an error. The CLI now escapes only characters the selected stream encoding cannot represent, and the new regression explicitly uses an ASCII console. Check the PR's current CI run for the final matrix result.
